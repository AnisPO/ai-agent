# AI Expense Agent

**Помощник по личным расходам** — ИИ-агент, который помогает вести учёт трат и анализировать бюджет.

## Назначение

Агент принимает от пользователя информацию о расходах на естественном языке, сохраняет их, распределяет по категориям и показывает сводки за период. Проект разрабатывается на языке **Python**.

## Планируемые возможности

- Добавление расходов с указанием суммы, категории и даты.
- Автоматическое распределение расходов по категориям (продукты, транспорт, развлечения и т.д.).
- Показ суммы расходов за выбранный период (день, неделя, месяц).
- Просмотр истории расходов и фильтрация по категориям.
- Экспорт отчёта о расходах в файл `CSV`.

## Примеры запросов пользователя

1. **Запрос:** «Потратил 500 рублей на продукты вчера».

   **Ожидаемый результат:** агент добавляет расход на 500 ₽ в категорию «Продукты» с датой вчерашнего дня и подтверждает сохранение.

2. **Запрос:** «Сколько я потратил на транспорт за последнюю неделю?»

   **Ожидаемый результат:** агент возвращает сумму всех расходов в категории «Транспорт» за последние 7 дней и, при желании, список этих трат.

## Подготовка окружения и запуск

Для запуска приложения необходимо установить Python версии 3.10 или выше.

### 1. Клонирование репозитория

Откройте терминал и выполните команды:

```bash
git clone https://github.com/AnisPO/ai-agent.git
cd ai-agent
```

### 2. Создание виртуального окружения

```bash
python -m venv venv
```

### 3. Активация виртуального окружения

Для Windows (Git Bash):

```bash
source venv/Scripts/activate
```

Для Windows (PowerShell):

```powershell
venv\Scripts\Activate.ps1
```

Для Linux и macOS:

```bash
source venv/bin/activate
```

### 4. Установка зависимостей

```bash
python -m pip install --upgrade pip
pip install -r requirements.txt
```

### 5. Запуск приложения

```bash
python main.py
```

После запуска появится приветственное сообщение. Для просмотра списка доступных команд введите `help`.

## Команды приложения

Приложение работает через консольный интерфейс. Пользователь вводит команду и необходимые аргументы.

| Команда | Аргументы | Назначение | Пример |
|---|---|---|---|
| `add` | `<сумма> <категория>` | Добавляет новый расход | `add 500 Продукты` |
| `show` | Нет | Показывает все сохранённые расходы | `show` |
| `change` | `<ID> <категория>` | Изменяет категорию расхода с указанным ID | `change 1 Транспорт` |
| `help` | Нет | Выводит справку по командам | `help` |
| `exit` | Нет | Штатно завершает работу приложения | `exit` |

## Проверка качества кода

Для проверки проекта используются `flake8` и `black`.

Команды необходимо выполнять из корневой папки проекта при активированном виртуальном окружении.

### 1. Проверка линтером flake8

```bash
python -m flake8 .
```
Команда проверяет Python-файлы проекта, включая автоматические тесты, на соответствие правилам оформления и наличие потенциальных проблем в коде.

При успешной проверке ошибок не выводится.

### 2. Проверка форматирования black

```bash
python -m black --check .
```

Ключ `--check` запускает проверку форматирования без изменения файлов.

Если файлы отформатированы правильно, команда сообщает, что изменений не требуется. Если форматирование отличается от требований `black`, программа покажет соответствующие предупреждения.

### 3. Автоматическое форматирование

Если требуется исправить форматирование исходных файлов, можно выполнить:

```bash
python -m black .
```

Эта команда автоматически форматирует Python-файлы проекта.

## Постоянное хранение данных

В лабораторной работе №3 реализовано постоянное хранение расходов в формате JSON.

- Файл данных по умолчанию: `data/expenses.json` в корневой папке проекта.
- Если файл ещё не существует, приложение начинает работу с пустым списком расходов.
- При первом добавлении расхода автоматически создаётся папка `data` и файл `expenses.json`.
- После добавления расхода или изменения его категории данные сразу сохраняются в JSON-файл.
- При следующем запуске приложения ранее сохранённые расходы загружаются автоматически.
- Каждая запись содержит уникальный `id`, сумму `amount` и категорию `category`. Поле `next_id` хранит следующий доступный идентификатор.
- Некорректный JSON или ошибка чтения и записи обрабатываются как ошибки хранилища.

Пример структуры файла `expenses.json`:

```json
{
    "expenses": [
        {
            "id": 1,
            "amount": 500.0,
            "category": "Покупки"
        }
    ],
    "next_id": 2
}
```

Файл `data/expenses.json` содержит локальные пользовательские данные и не добавляется в Git. Для этого он указан в `.gitignore`.

## Автоматические тесты

Для проверки работы приложения используются `pytest` и `pytest-cov`.

Тесты находятся в папке `tests/`:

- `test_storage.py` — проверка хранения, загрузки, изменения расходов и обработки ошибок.
- `test_agent.py` — проверка логики добавления, просмотра и изменения расходов.
- `test_cli.py` — проверка команд консольного интерфейса.
- `test_main.py` — проверка запуска приложения.

### Запуск тестов

```bash
python -m pytest
```

### Запуск тестов с отчётом о покрытии

```bash
python -m pytest --cov=agent --cov=storage --cov-report=term-missing
```

Команда запускает автоматические тесты и формирует отчёт о покрытии кода модулей agent.py и storage.py. В отчёте отображаются количество выполненных и пропущенных операторов, процент покрытия и номера строк, которые не были выполнены во время тестирования.

При расчёте покрытия исключены только строки, отвечающие за форматирование и вывод пользовательских сообщений, с помощью комментария # pragma: no cover. Проверки входных данных, работа с хранилищем и обработка ошибок остаются в области измерения покрытия.

В текущей версии проекта тесты проверяют в том числе:

- первый запуск без существующего файла данных;
- сохранение расходов и восстановление после повторного запуска хранилища;
- сохранение изменения категории;
- сохранение остальных записей без изменений;
- обработку некорректного JSON;
- обработку ошибок сохранения;
- проверку некорректных пользовательских данных;
- работу команд консольного интерфейса с использованием временного файла хранилища, чтобы тесты не изменяли реальные пользовательские данные.
